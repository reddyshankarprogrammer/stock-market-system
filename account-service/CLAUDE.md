# CLAUDE.md: account-service

Read `README.md` in this folder, then the `docs/account-service-*.md` file for the area you change (API, database, ledger, statement import, security).

## Hard rules

1. **Schema = Flyway.** Any entity change needs a new `src/main/resources/db/migration/V<next>__<what>.sql`. Never edit an applied script (V1–V11 are applied in dev). Hibernate runs `ddl-auto: validate`; the Testcontainers tests catch mismatches.
2. **Enums are VARCHAR.** Every `@Enumerated(EnumType.STRING)` field also has `@JdbcTypeCode(SqlTypes.VARCHAR)`, or Hibernate validation expects a MySQL ENUM. Check the column length fits the longest value.
3. **Only `LedgerService` changes a balance** (`postDebit` / `postCredit`). Callers must hold the row lock from `AccountAccessService.getOwned…ForUpdate` / `getActiveAccountForUpdate`, inside a transaction (those methods are `Propagation.MANDATORY`).
4. **Tracking accounts never move cash.** Manual and imported trades, charges and taxes do not touch the ledger. `account.isTracking()` / `brokerName.isPlatformTraded()` decide which path applies.
5. **Ownership.** Reads go through `accountAccessService.getOwnedAccount` (owner or ADMIN); writes through the `ForUpdate` variants (owner only). The caller is the `X-User-Id` header; never take a user id from a body.
6. **Admin endpoints** call `RequestUser.requireAdmin()` and are listed in the gateway's `ADMIN_PATHS`.
7. **Money:** use `service/model/Money`: amounts 2 decimals, quantities/average prices 8, HALF_UP. Never `double`.
8. **DTOs** are generated by a script (`@Data @Builder`, Swagger `@Schema`, Bean Validation). Keep that style when adding one by hand. Responses never expose entities.
9. **Mapping:** add a method to `mapper/AccountMapper`. `unmappedTargetPolicy = ERROR` means every new response field needs a source or `@Mapping(target=…, ignore=true)`. Quantities use `qualifiedByName = "plainQuantity"`.
10. **Audit** every state change with `auditService.logAccountAction(accountId, AuditAction, details, request, response)` in the same transaction.
11. **Events** are published with Spring's `ApplicationEventPublisher` and sent to Kafka by `AccountEventPublisher` after commit; never call `KafkaTemplate` inside business logic.

## Gotchas

- Boot 4 / Jackson 3: Jackson classes are `tools.jackson.*` (annotations stay `com.fasterxml.jackson.annotation`). `JsonMapperBuilderCustomizer` is in `org.springframework.boot.jackson.autoconfigure`; `@AutoConfigureMockMvc` in `org.springframework.boot.webmvc.test.autoconfigure`.
- MockMvc multipart builders do not extend `MockHttpServletRequestBuilder` in Spring 7; use `AbstractMockHttpServletRequestBuilder<B>` generics.
- Self-invocation skips `@Transactional`. `StatementImportServiceImpl` and `AccountStatementServiceImpl` use a `TransactionTemplate` on purpose: file I/O and parsing run outside transactions, persistence in one.
- `@Builder` ignores field initializers unless they have `@Builder.Default` (see `Trade.brokerage`, `InvestmentAccount.brokerName`).
- Both integration test classes must keep **identical** context configuration (`@SpringBootTest(properties=…)`, the same `@MockitoBean`s), or a second set of containers starts and the suite slows down sharply.
- The gateway only forwards paths listed in its account-service route; a new top-level path (e.g. `/api/v1/xyz/**`) must be added there.
- On Windows the running service locks its jar; stop it before `mvnw package`.

## Recipes

**Add a field to an existing table**
1. `V<next>__<table>_<field>.sql` with `ALTER TABLE … ADD COLUMN …` (default for NOT NULL; backfill with `UPDATE` if needed).
2. Entity field (+ `@JdbcTypeCode` for enums, `@Builder.Default` if it has a default).
3. Response DTO field + `AccountMapper` mapping.
4. `docs/account-service-database.md` (table + migrations list) and `docs/account-service-api.md`.
5. `.\mvnw.cmd test` (validates the schema against the real MySQL image).

**Add an endpoint**
1. Service interface method + implementation (`@Transactional`, ownership via `AccountAccessService`, audit).
2. Controller method with `@Operation`, `@Parameter(description = ApiHeaders.USER_ID_DESCRIPTION) @RequestHeader(ApiHeaders.USER_ID)`, `@Valid` body.
3. New exception? Map it in `GlobalExceptionHandler`.
4. New path prefix? Add it to the gateway route.
5. Integration test in `AccountServiceV2Tests`; Postman request in `docs/postman/generate_collection.py` (then `python generate_collection.py .`); API doc.

**Support a new broker's statement**
1. `BrokerName` value; include it in `supportsStatementImport()`.
2. `class XyzParser extends AbstractConfigurableParser` returning the broker (no other code).
3. `account.import.brokers.xyz` in `application.yaml`: `trade-mode`, `date-formats`, `columns` aliases, optional `charges`/`summary` sections.
4. A test in `StatementParsersTest` with a realistic sample; add a sample to `docs/postman/samples/`.
5. `docs/account-service-statement-import.md` broker table.

**Fix a column mapping for an existing broker**: edit only `application.yaml` (aliases are tried in order; first match wins), restart, `POST /api/v1/statements/{id}/reprocess`.

**Add a fee or tax rule**: new Flyway script inserting into `fee_master` / `tax_master` (deactivate the old row rather than updating it, so historic charges stay explainable).
