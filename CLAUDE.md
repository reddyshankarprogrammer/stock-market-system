## 2. How the services talk

```
client --JWT--> api-gateway --X-User-Id/X-User-Role--> services
```

| From | To | How | What |
|---|---|---|---|
| order-service | market-data-service | Feign | price per order |
| order-service | user-service | Feign | `funds/deduct`, `funds/credit` (internal) |
| portfolio-service | market-data-service | Feign | live prices |
| account-service | user-service | Feign | `/me` (validate ACTIVE), `/{id}` (admin lookups) |
| account-service | market-data-service | RestClient | prices |

| Kafka topic | Producer | Consumers | Payload (map) |
|---|---|---|---|
| `user.registered` | user-service | notification | userId, email, firstName, lastName, walletBalance |
| `order.executed` | order-service | portfolio, notification | orderId, userId, symbol, type, quantity, price, totalAmount, status, timestamp |
| `order.failed` | order-service | notification | same + reason |
| `stock.price.updated` | market-data | none | symbol, price, timestamp |
| `account.trade.executed`, `account.fund.transaction` | account-service | none | see account-service README |

Ledgers are separate: user-service wallet + order-service + portfolio-service form one trading path; account-service is an independent ledger of investment accounts.

## 3. System-wide rules

1. **Identity** comes only from the gateway headers `X-User-Id`, `X-User-Role` (`USER`/`ADMIN`, from the JWT `role` claim). Never accept a user id from a request body. Services trust these headers, so service ports must stay private.
2. **Authorization**: every endpoint that addresses a user's data checks ownership; ADMIN may read but changes stay owner-only. Internal and admin-only paths are constants in `api-gateway/.../JwtAuthFilter` (`PUBLIC_PATHS`, `INTERNAL_PATHS`, `ADMIN_PATHS`).
3. **Boot split**: user-service is Boot 3 (Jackson 2, `JsonSerializer`); all others Boot 4 (Jackson 3 `tools.jackson.*`, `JacksonJsonSerializer`, `spring-boot-starter-webmvc`). Check the `pom.xml` before copying code between services. Spring Cloud 2025.1.3 everywhere it is used.
4. **Configuration**: all settings come from `.env` at the repo root, imported by every service (`spring.config.import: optional:file:../.env[.properties]`). Reference `${VAR}`; never hard-code hosts, ports or secrets. `JWT_SECRET` has no default and must be identical for user-service and the gateway.
5. **Hosts pattern**: `.env` hosts (`mysql`, `kafka:29092`) only resolve inside Docker. Services declare a top-level `hosts:` block (localhost) that the `docker` profile overrides (market-data-service still hard-codes localhost). A `SPRING_PROFILES_ACTIVE` inside `.env` does not activate profiles; only a real environment variable does.
6. **Kafka payloads are flat JSON maps**; consumers read them with `ErrorHandlingDeserializer` → `JacksonJsonDeserializer` into `HashMap` with `spring.json.use.type.headers: false`. Only add fields; never rename existing ones.
7. **Schema**: account-service uses Flyway (new `V<n>` script per change, never edit applied ones, `ddl-auto: validate`). The others use Hibernate `ddl-auto: update`: new NOT NULL columns need a DB default.
8. **Errors** use the shared body `{timestamp, status, error, message}` from each service's `GlobalExceptionHandler`; prefer typed exceptions over message matching.
9. **Money** is `BigDecimal`, never `double`.
10. Keep new code inside the service's existing base package.

## 4. Commands

```powershell
.\scripts\start-all.ps1            # docker compose up + build + start all 7 + wait for health
.\scripts\start-all.ps1 -NoBuild   # start existing jars
.\scripts\stop-all.ps1 [-Infra]    # stop services (and Docker)
docker compose up -d               # infrastructure only

# per service, from its folder
.\mvnw.cmd test
.\mvnw.cmd test -Dtest=ClassName#method
.\mvnw.cmd -q package -DskipTests
.\mvnw.cmd spring-boot:run
```

Logs: `logs/<service>.log`; process ids: `logs/pids.txt`. No linter is configured.

| Tests | Need |
|---|---|
| user-service, api-gateway, order-service, notification-service | nothing |
| account-service (44, ~1 min) | Docker (Testcontainers starts its own MySQL + Kafka) |
| market-data-service, portfolio-service (`contextLoads`) | docker compose infrastructure |
| End to end: `docs/postman` with Newman | all services running |

## 5. Implementing a change that spans services

1. Read both services' `CLAUDE.md`.
2. Contract first: REST DTO or Kafka map fields; keep them backward compatible (add, do not rename).
3. Producer/provider side, then consumer side; update Feign clients / DTOs that read the contract.
4. New public, internal or admin path → gateway `JwtAuthFilter` lists + `JwtAuthFilterTest`; new path prefix → gateway route.
5. Tests in each touched service; restart the touched services; run the Postman collection:
   ```powershell
   cd docs\postman; npx newman run stock-market-system.postman_collection.json -e stock-market-local.postman_environment.json --delay-request 300
   ```
6. Documentation in the same change: the service `README.md`/`CLAUDE.md`, `docs/` (API, database, sequence diagrams as relevant), `docs/changelog.md`, and new Postman requests in `generate_collection.py`.

## 6. Environment pitfalls (Windows workstation)

- A running service locks `target/*.jar`: stop it (`stop-all.ps1` or its pid in `logs/pids.txt`) before `mvnw package`.
- Windows PowerShell 5.1: native tools writing to stderr (docker, mvnw) abort scripts that use `$ErrorActionPreference = "Stop"`; check `$LASTEXITCODE` instead.
- Docker Desktop must be running for infrastructure and for account-service tests.
- Long Bash heredocs can be cut off by the tool; write scripts to a file and run the file.
- `curl` from Git Bash cannot read `/tmp/...` paths for `-F file=@`: use a relative path.
- Create an ADMIN: `UPDATE users SET role='ADMIN' WHERE email='…';` in the `mysql` container, then log in again.

## 7. Known system-level gaps

- portfolio-service `GET /api/v1/portfolio/{userId}` has no ownership check.
- order-service SELL is not checked against holdings; no compensation if saving fails after funds moved.
- Market data only simulates six US stocks; external price APIs are unused.
- Refresh tokens (`POST /api/v1/users/refresh`) are stateless: not rotated, not revocable, no logout endpoint; login with unknown e-mail returns 404 and login ignores the user status.
- No production email provider yet: password-reset emails only work locally (Mailpit) until `MAIL_HOST`, `MAIL_FROM` and `APP_BASE_URL` are set for user-service in `k8s/user-service/configmap.yaml` (plus credentials in its Secret).
- Notifications are in memory; account-service Kafka events have no consumers.
- Broker statement column mappings are not yet confirmed with real files.
- `user-service/application-docker.yaml` and `JwtService` still contain fallback values for the DB password and `jwt.secret`; Kubernetes always sets them, but the fallbacks should be removed.
- The 9 reserved Kafka topics (`account-created` ... `notification-created`) have no producer or consumer.

## 8. Kubernetes, CI/CD and GitOps

Docs: `docs/kubernetes-architecture.md`, `cicd-pipeline.md`, `github-actions-guide.md`, `argocd-guide.md`, `operations-runbook.md`.

| Where | What |
|---|---|
| `k8s/<service>/` | Deployment, Service, ConfigMap, Secret **template**, HPA, PDB, ServiceAccount, `kustomization.yaml` (image tag) |
| `k8s/{namespaces,security,ingress,mysql,redis,kafka,monitoring}/` | platform manifests; one Argo CD application per folder (`k8s/argocd/argocd-applications.yaml`) |
| `k8s/*/*-values.yaml` | Helm values used by `scripts/install-*.sh` (not applied by Argo CD) |
| `scripts/*.sh` | K3s and platform installers (bash, Ubuntu 24.04); versions in `scripts/lib/versions.env` |
| `.github/workflows/` | `ci.yml`, `security.yml`, `cd.yml` (manual approval: environment `production`), `release.yml` |

Rules:

1. Argo CD deploys `main`; never `kubectl edit/apply/set image` in the cluster (self-heal reverts it). Image tags in `k8s/<service>/kustomization.yaml` change only through `cd.yml`.
2. Secrets never go to Git (the AppProject blacklists `Secret`). A new secret key: `.env.example` + `k8s/<svc>/secret.yaml` template + `scripts/create-secrets.sh`.
3. New non-secret setting: environment variable in `k8s/<svc>/configmap.yaml` (relaxed binding, e.g. `HOSTS_USER_SERVICE`, `SPRING_DATASOURCE_*`). Pods do not restart on ConfigMap changes: `kubectl rollout restart`.
4. Pods set `enableServiceLinks: false`: otherwise Kubernetes injects `<SERVICE>_PORT=tcp://...` and breaks `${USER_SERVICE_PORT}`-style settings.
5. New Kafka topic: declare it in `k8s/kafka/kafka-topics.yaml` first (`auto.create.topics.enable=false`).
6. New service: Dockerfile, `k8s/<svc>/`, Argo CD application, the service lists in `ci.yml`, `security.yml`, `cd.yml`, `release.yml`, `dependabot.yml`, a dashboard in `generate_dashboards.py`.
7. Dashboards: edit `k8s/monitoring/dashboards/generate_dashboards.py`, run it, commit the JSON (CI fails on drift).
8. Images are distroless (no shell) and run read-only as uid 65532; write only to `/tmp` or a mounted volume.
9. Shell scripts and manifests keep LF line endings (`.gitattributes`); lint with `shellcheck -x scripts/*.sh` and `kubectl kustomize k8s/<folder>`.
